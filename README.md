### 项目简介

**CUCoreLib.KrokMP.SaveHotfix** 用于修复 *Casualties Unknown Demo* 中 CUCoreLib 与 KrokMP 同时安装时出现的多人存档冲突。

同时使用 CUCoreLib 和 KrokMP 后，载入多人存档可能出现：

- 主机背包物品被载入到其他玩家身上；
- 其他玩家的背包被清空；
- 不同角色之间的背包数据发生错配。

完全卸载 CUCoreLib 的存档补丁可以恢复 KrokMP 的玩家背包隔离，但也会导致通过 CUCoreLib 注册的自定义 Mod 物品无法载入。本项目采用选择性修复方式：只关闭存在玩家身份混淆风险的保存和恢复链路，同时保留 CUCoreLib 的自定义物品载入 Transpiler。

**1.0.0** 已通过实际多人联机测试：各玩家背包能够正确独立恢复，基于 CUCoreLib 的自定义物品也可以正常保存和载入。

### 工作原理

KrokMP 会分别保存和载入每一名多人角色。CUCoreLib 原有的扩展存档系统主要按单机作用域设计，保存和恢复时依赖当前本地角色作为目标。

当 KrokMP 依次处理多个玩家存档时，CUCoreLib 的旧保存逻辑缺少稳定的玩家身份上下文，可能将某名玩家的数据恢复到另一名角色。

本热修复会：

1. 移除 CUCoreLib 在 `SaveSystem.SaveGame` 上不安全的 Postfix；
2. 移除 CUCoreLib 在 `SaveSystem.TryLoadGame` 上不安全的 Prefix；
3. 保留 `TryLoadGame` 上用于解析 CUCoreLib 自定义物品的 Transpiler；
4. 禁用 CUCoreLib 的全局多人 `save` 快照模块；
5. 清除尚未应用的 CUCoreLib 待恢复数据。

因此，KrokMP 继续负责每名玩家的背包存档隔离，CUCoreLib 则继续负责解析和实例化已注册的自定义物品类型。

A compatibility hotfix that prevents CUCoreLib from corrupting or mixing KrokMP multiplayer inventories while preserving the loading of CUCoreLib-based custom items.

### Overview

**CUCoreLib.KrokMP.SaveHotfix** resolves a multiplayer save conflict between CUCoreLib and KrokMP for *Casualties Unknown Demo*.

When CUCoreLib and KrokMP are installed together, loading a multiplayer save may cause:

- the host's inventory to be restored to another player;
- remote players' inventories to be emptied;
- inventory data to be assigned to the wrong character.

Completely disabling CUCoreLib's save patches fixes the inventory isolation problem, but it also prevents custom items registered through CUCoreLib from loading. This project applies a selective workaround: it disables only the unsafe save and restore paths while retaining CUCoreLib's custom-item loading transpiler.

Version **1.0.0** has been tested in an actual multiplayer session. Player inventories remained isolated correctly, and CUCoreLib-based custom items could still be saved and loaded.

### Compatibility

Tested with:

- *Casualties Unknown Demo* 7.0.1
- BepInEx 5.4.23.5
- KrokMP 4.0.1
- CUCoreLib 1.0.3-alpha

Special thanks to the following players for helping test this project: 
下雪吃火锅
叶er

The hotfix was also designed to work with CUCoreLib nightly 1.0.4, but the tested baseline is CUCoreLib 1.0.3-alpha.

### How it works

KrokMP saves and loads each multiplayer character separately. CUCoreLib's original extended-save implementation was designed around a single local player and uses the active local body as its save and restore target. During KrokMP's sequential processing of multiple player saves, this missing player identity context can cause data to be restored to the wrong character.

The hotfix:

1. removes CUCoreLib's unsafe postfix from `SaveSystem.SaveGame`;
2. removes CUCoreLib's unsafe prefix from `SaveSystem.TryLoadGame`;
3. preserves CUCoreLib's custom-item loading transpiler on `TryLoadGame`;
4. disables CUCoreLib's global multiplayer `save` snapshot module;
5. clears any pending CUCoreLib restore payload.

KrokMP therefore remains responsible for per-player inventory persistence, while CUCoreLib can still resolve and instantiate registered custom item types.

### Known limitations

This hotfix preserves the persistence of CUCoreLib-registered item objects. It does not fully redesign CUCoreLib's provider-based extended save system.

Mods that depend on CUCoreLib providers such as the following may still lose additional internal state:

- body providers;
- limb providers;
- item save providers;
- world providers;
- global providers.

A complete upstream solution would need to pass an explicit target character and stable player identifier through CUCoreLib's capture and restore APIs instead of relying on the active local player.
